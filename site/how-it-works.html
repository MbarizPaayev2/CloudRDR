Cryptographic Pipeline Walkthrough

How CloudRDR defends cloud storage

A real-time interactive guide to the 6-stage autonomous detection, sub-10s IAM containment, and AEAD-verified recovery lifecycle.

01
STAGE 01 // IMMUTABLE BASELINE

1. Establishing the cryptographic baseline

Before any attack occurs, every file in the protected bucket is read via streaming SHA-256 hashing without buffering the full file into server RAM. The resulting cryptographic digests are sorted deterministically and assembled into a binary Merkle tree.

STAGE 02 // REAL-TIME TELEMETRY

2. Sliding-window polling agent

A lightweight background monitor agent observes bucket storage events (file creations, modifications, and deletions) on a 10-second polling cadence. It computes rolling change counts within a 60-second sliding time window.

What you will see in the demo: The Detection Velocity Chart plots change rates in real time, comparing current file activity against configured threshold lines.

03
STAGE 03 // VELOCITY TRIPWIRE

3. Velocity and canary threshold classification

The engine evaluates the change rate (unique modified files / total files). Changes under 10% are classified as NORMAL, 10–30% as SUSPICIOUS, and 30%+ as RANSOMWARE. In addition, decoy canary files (such as canary/tripwire_sentinel.docx) act as zero-tolerance tripwires: modifying or deleting any canary triggers an immediate ransomware verdict regardless of rate.

What you will see in the demo: The Verdict Badge switches to pulsing red RANSOMWARE, and the Canary Sentinel Card displays the exact timestamp the decoy was touched.

04
STAGE 04 // IMMEDIATE CONTAINMENT

4. Sub-10s automated IAM account freeze

Upon a ransomware verdict, CloudRDR immediately attaches an IAM Deny-All write policy to the compromised cloud credentials. All write, overwrite, and delete API calls are blocked at the cloud control plane in under 10 seconds. An incident case file is generated and signed with an RFC 8032 Ed25519 asymmetric signature.

What you will see in the demo: The Account Status badge turns frost-blue with label FROZEN (READ-ONLY) and a new case file appears in the Incidents queue.

05
STAGE 05 // TAMPER-EVIDENT AUDIT

5. Cryptographic hash-chained audit ledger

Every security action (baseline seal, freeze policy attachment, incident sign, restore) is appended to a hash-chained audit log. Each entry embeds the SHA-256 digest of the previous entry. If an attacker gains database access and modifies a record, the subsequent block links visibly break.

06
STAGE 06 // VERIFIED RESTORE

6. AEAD authenticated recovery and 100% verification

CloudRDR restores files from AES-256-GCM encrypted backup storage. The recovery process validates the GCM authentication tag before returning plaintext bytes. Every restored file is re-hashed with SHA-256 and matched against the pre-attack baseline. If any hash differs or tag fails, the file is rejected. The incident only transitions to resolved when 100% of files are verified.

What you will see in the demo: The Restore progress bar fills, leaves return to green on the Merkle tree, and a final "100% verified" banner confirms that the Merkle Root matches the original baseline.

Plain-language security glossary

SHA-256

A mathematical algorithm that converts any file into an exact 64-character fingerprint. If even a single byte inside the file changes, the entire fingerprint changes completely.

Merkle tree

A hierarchical tree of hashes where pairs of file fingerprints are combined repeatedly until they form a single "Root Hash". This single root proves the integrity of thousands of files at once.

Canary (decoy) file

A silent trap file placed inside cloud storage that legitimate staff never touch. If any process attempts to modify or delete it, the system immediately recognizes a ransomware attack.

Ed25519 digital signature

A modern public-key cryptographic signature that proves an incident record was officially created by CloudRDR and has not been altered by an attacker.

AES-256-GCM & AEAD

Authenticated Encryption with Associated Data. It encrypts backup files with military-grade 256-bit keys and includes an authentication tag that detects any unauthorized tampering before decrypting.

Hash chain

A continuous sequence of log records where each record contains the fingerprint of the previous record. This makes it impossible to delete or rewrite past audit logs without detection.
